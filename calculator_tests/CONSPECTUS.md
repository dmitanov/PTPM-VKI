# Лабораторная работа 6 — Автоматизированное UI-тестирование с POM

## Цель работы

Изучить основы автоматизированного UI-тестирования, освоить паттерн Page Object Model и получить практические навыки работы с Selenium WebDriver и unittest.

## Теоретический минимум

### UI-тестирование

UI-тесты проверяют приложение через пользовательский интерфейс: вводят данные, нажимают кнопки, выбирают значения и считывают результат. В отличие от юнит-тестов, они проверяют интеграцию браузера, разметки, JavaScript и бизнес-логики.

### Selenium WebDriver

Selenium WebDriver — инструмент управления браузером из кода. Он позволяет запускать браузер, находить элементы по локаторам, выполнять действия и получать состояние страницы. В проекте используется Selenium 4: драйвер подбирается автоматически через Selenium Manager.

Основные компоненты:

- `WebDriver` — управление сессией браузера;
- `By` — стратегии поиска элементов (`ID`, `CSS_SELECTOR`, `XPATH` и другие);
- `WebDriverWait` + `expected_conditions` — явные ожидания;
- `Select` — работа с `<select>`;
- `EdgeOptions` / `ChromeOptions` / `FirefoxOptions` — настройки запуска, включая headless.

### Page Object Model

POM — паттерн, при котором каждая страница приложения описывается отдельным классом. Класс хранит локаторы и методы взаимодействия, а тесты используют только эти методы.

Преимущества:

1. Тесты не зависят от конкретных локаторов.
2. Локатор меняется в одном месте.
3. Тесты читаются как бизнес-сценарии.
4. Повторные действия выносятся в методы страницы.

Прямое обращение `driver.find_element` из тестов запрещено: все действия инкапсулированы в `CalculatorPage`.

### unittest

`unittest` — встроенный фреймворк тестирования Python. Тестовый класс наследуется от `unittest.TestCase`. Методы `setUp()` и `tearDown()` создают и закрывают браузер перед каждым тестом, обеспечивая независимость тестов.

## Фрагмент Page Object

```python
class CalculatorPage:
    _FIRST_NUMBER = (By.CSS_SELECTOR, 'input[ng-model="a"]')
    _OPERATION = (By.CSS_SELECTOR, 'select[ng-model="operation"]')
    _RESULT = (By.CSS_SELECTOR, "b.result")

    def enter_first_number(self, number):
        field = self._wait_for(self._FIRST_NUMBER)
        field.clear()
        field.send_keys(str(number))
        return self

    def get_calculated_value(self):
        return self.get_result_text().rsplit("=", 1)[-1].strip()
```

## Фрагмент теста

```python
def test_addition(self):
    self.assert_number(19, 12, 7, "+")

def test_division_by_zero_returns_null(self):
    self.assertEqual(self.page.calculate(10, 0, "/"), "null")
```

## Покрытие тестами

| Группа | Тесты |
| --- | --- |
| Базовые операции | сложение, вычитание, умножение, деление |
| Граничные значения | отрицательные числа, большие числа, десятичное деление |
| Особые случаи | `10 / 0` → `null`, `0 / 0` → `null` (Angular 1.0.7) |
| Кнопки | `+1` и `-1` для первого и второго операнда |
| Состояние интерфейса | стартовое значение `0 + 0 = 0`, список операций |

## Важное замечание об операции `**`

В задании указана необходимость тестировать `**`, но реальный интерфейс Simple Calculator содержит только `+`, `-`, `*`, `/`. Операция `**` отсутствует в `select`, поэтому её нельзя выбрать через UI. Вместо искусственной подмены DOM добавлен тест, который проверяет фактический список доступных операций. Это ограничение зафиксировано в `README.md`.

## Запуск

```bash
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install selenium
python -m unittest discover -s tests
```

По умолчанию используется Edge в headless-режиме. Для смены браузера или отображения окна используются переменные `BROWSER` и `HEADLESS`.

## Вывод

Использование Page Object Model сделало тесты читаемыми и устойчивыми к изменениям разметки. Selenium WebDriver совместно с unittest позволяет автоматизировать пользовательские сценарии в браузере, а явные ожидания повышают стабильность тестов. Анализ реального приложения показал два расхождения с техническим заданием: операция `**` в интерфейсе отсутствует, а деление на ноль отображается как `null` вместо `Infinity`/`NaN`. Оба факта были корректно отражены в тестах и документации.
